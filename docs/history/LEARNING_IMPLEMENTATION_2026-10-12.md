## First stage: replay engine and evidence boundaries

Implemented in `backend/src/fpl_app/evaluation/strategy.py` and `provenance.py`. Replay policies receive the supported planning horizon capped at GW38. Every week is independently validated, only the first executes, and later origins replan against their own frozen forecasts. Delayed transfers are proposals, not executed early. Greedy remains a one-event comparator. Reports record planning horizon, plan fingerprint, full forecast-path net points and executed-event points separately.

Evidence modes:

| Mode | Required evidence | Claim |
| --- | --- | --- |
| `prospective_strict` | Frozen manifest reference; exact run/catalogue/schedule; source/model/policy/mapping bytes, checksums and capture/availability times; matching policy identifier and implementation digest | Retained input/timing consistency, subject to trusted capture |
| `historical_reconstructed` | Actual prediction origin plus explicit simulated fitting-label availability no later than simulated information origin | Qualified historical research, never past deployment |
| `synthetic_mechanics` | Authored inputs and outcomes, caller-asserted timing | Mechanics only |
| `retrospective_assumed` | Existing legacy callers, caller-asserted timing | Unverified research only |

Unknown modes fail. Generative simulation is not implemented. Strict mode requires live input contracts; authored tests use those schemas only to test gates and do not constitute live evidence. Local manifest timestamps are not external attestations. Caller-supplied historical label timing does not itself audit training features or prove that all leakage was removed.

`ReplayOrigin.manifest_path` and `manifest_sha256` point to a local `ReplayManifest` JSON envelope and its previously frozen SHA256. The envelope contains `forecast`, `players`, `deadline`, `information_available_at`, `schedule_complete_events`, `policy_identifier`, `implementation_sha256` and `artifacts`. Obtain the implementation digest with `implementation_sha256()` at capture time. Each artifact has a source/model/policy/mapping role, a unique relative basename, SHA256, capture and availability times. Policy bytes must match its current source module; the package digest also binds domain/planner dependencies. Closures are rejected in strict mode. An advanced model requires its manifest and every listed payload with matching identity and timing. A complete declared fixture schedule is required, including explicit wholly blank events. Missing player projections for scheduled fixtures fail normal input validation.

The expected manifest digest must come from a trusted retained pre-deadline reference. Do not regenerate it from today's files to claim a historical prospective capture. Immutable journal capture and manual execution reporting are implemented in D02. The existing financial ledger is reused; dynamic price/chip sequence optimisation is still pending.
